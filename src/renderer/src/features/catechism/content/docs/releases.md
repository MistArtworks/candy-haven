# RELEASES

DISCOGRAPHY, as the website shows it: which releases visitors see, the home
page shelf, and the covers. Behind the DISPATCH sign-in.

![releases-01-list.png](releases-01-list.png)

## Publish everything, once

Until it is pressed, the website shows its own releases. **Publish everything**
lists every release first, in three groups: shown on the website, drafts kept
hidden, and the ones that can't go yet, each with why. It sends them all in one
request and switches the website over for good; from then on it shows only what
is sent from here.

## After that, a release goes on Done

Edit a release in DISCOGRAPHY and press **Done**: the fields that changed since
it was last sent go to the website, and nothing else, so an edit the other
computer made to another field isn't undone. A release raised since goes the
same way. If the website can't be reached, the release waits and goes with
**Sync now**, on signing in, or when the console starts.

| Chip              | Means                                                        |
| ----------------- | ------------------------------------------------------------ |
| `NOT SENT`        | The website has never had it from here                       |
| `ON THE WEBSITE`  | The website has it as it is here                             |
| `CHANGED`         | Edited here since it was last sent                           |
| `COVER TO SEND`   | Only its cover is new; it follows on its own                 |
| `WAITING TO SEND` | A send that couldn't reach the website                       |
| `CAN'T GO ON`     | The website can't show it as it is (no tracks, say)          |

## Shown or hidden

Whether visitors see a release follows its status in DISCOGRAPHY:

- **DRAFT**: hidden until its release day. The row says **Hidden · draft**.
- **SCHEDULED**: shown before its day, with its pre-save links.
- **RELEASED**: shown. A release turns RELEASED on its day by itself.

**Show** on a release that isn't out yet makes it SCHEDULED (it needs a date);
**Hide** makes it a DRAFT. On a release that's out, Hide keeps it off the
website by hand and Show puts it back.

## Pick, then Update

Nothing on this page reaches the website on its own. Tick releases, or the box
above the list for every one shown, and pick what to do from the bar: **Show**,
**Hide**, **Add to shelf**, **Remove from shelf**, **Send**. **More** picks the
drafts, the hidden ones or what's to send. Each row also has a **⋯** menu for
itself alone.

What's picked is held, and each row's tags read `NOW → AFTER` with a gold mark
down its edge. The **Update** bar at the foot of the page says how many changes
there are and sends them all in one request; **Discard** drops them. If the
website says no, nothing there changes and the picks stay.

## The home page shelf

Up to eight releases, in the order set in its panel: **↑** and **↓** move one,
**×** takes it off, and those go with Update too. Only a release visitors see can
go on it, and hiding one takes it off. With none picked, the website shows the
newest eight.

## Covers and tapes

![releases-02-covers.png](releases-02-covers.png)

Each release's cover goes to the website after the release itself, shrunk here
to 750 on its shorter side. The website makes it a 750×750 WebP and, from it,
the release's tape for the shelf: the cassette with the cover printed on its
insert. A cover changed in DISCOGRAPHY goes again; a release removed takes its
cover and tape with it. Covers go one at a time in the background, so an Update
waits for one cover at most.

## What it's doing

While anything is going to the website, a strip under the filters says what:
**Publishing everything**, **Updating the website**, **Syncing**, **Sending an
edit**, and **Sending covers** with how many have gone.

## The other computer's

Releases on the website that the other copy of the console sent are listed
under **From the other computer**. They can be shown, hidden and put on the
shelf here; they're edited there. A draft from there can only be scheduled
there.

> Both copies keep their own DISCOGRAPHY. In practice one computer publishes
> and the other edits only when asked.
